### 执行期另外三个技术性改判（不占 R 编号）

- **D1**（`5a6853f`）：Vitest 5 会把 `beforeEach` 的**返回值**当作 teardown 回调并零参调用，brief 里 `beforeEach(() => mockedStream.mockReset())` 因此会在每个用例后被再次调用 mock → 改为块体 `{ mockedStream.mockReset(); }`，断言不受影响。
- **`onUnhandledFrame` 不是笔误**（终审曾怀疑，经查 `node_modules/msw/lib/_chunks/shared-options.d.ts:15` 确认 msw 3.0.3 的选项名确实如此），保持原样。
- **React 重复 key**（`59ee1b1`）：一轮里同一 `ref` 可能有多条 citation（医案链 + 检索命中的 `case:11`），`RetrievalProgress` 用 `ref_type:ref_id` 作 key 在真实浏览器控制台报错——这是 Playwright 抓出的、jsdom 结构上不可能发现的产品缺陷。

## 三、已知边界（四条，均已在 §6.7 / §13 逐字写明）

1. **医案抽屉不高亮**：后端只为 `evidence` 类 citation 写 `snippet`（`backend/app/rag/builders.py:66-74`），`case` 类为空串，按规格 §7.4「找不到则不高亮」如实呈现 0 个 `mark`；高亮的命中分支在桂枝汤出处抽屉实测为 1 个 `mark`，两端都有 e2e 锁定。
2. **混合方的表头提示**：`backend/app/api/formulas.py:277-278` 的 formula 级 `dose_complete` 取「任一变体全 `exact`」，故五苓散的卡/详情顶部**不挂**「本方剂量不完全可执行」；行级 `—` + 中文状态与本轮回答提示均正常。属 M2 数据契约语义，需后端定口径（issue #2）。
3. **`general_note` 无真实数据**：M3 恒返回 `null`，端到端无从验证，只做到组件级断言（`border-dashed` + `<aside>` 标签名 + 「非本库内容」文案）。
4. **17 字段问诊表的 Tab 遍历顺序未在 e2e 演练**：三态选择与提交已用纯键盘事件（`focus()` + `Space` + `Enter`，零 `click()`）跑通，但整表 tab-order 依赖 axe + 人工复核（规格 §8.6 要求，issue #4）。

另有三条 M4 明确不做的既有项：FR-14 原文检索、管理端鉴权（E2）、`HashingEmbedder` 下的语义召回质量（见 E3）。
