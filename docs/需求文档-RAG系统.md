# 中医经方知识库 · RAG 前后端系统需求文档（PRD v0.1）

> 目标：把本仓库的 `distilled/` 蒸馏库、`.claude/skills/` 五个临床能力与 `PIPELINE.md` 接诊 SOP，
> 转化为一套**前后端实现 + RAG 问答**的 Web 系统。
> 核心原则不变：**所有结论严格基于本地知识库，查不到不写、不臆造**。

**现状问题（2026-10-28 实测，入库前必须处理）**：

1. **药名两套体系，外键默认 join 不上**（影响 FR-2/FR-7/FR-8/FR-13）。`04-神农本草经/中药库.md` 的
   `药名` 列用**本经古名**——实测 `牡桂` 命中、`桂枝` 未命中；`茈胡` 命中、`柴胡` 未命中；`杏仁` 未命中。
   而 `方剂库-经方组成.md` 的组成列用**现代名**（`**桂枝** 半两（去皮）`）。
   → 建库时必须先跑**药名归一**（复用 `formula_verify.py` 的炮制前缀剥离 + 同义词归一，
   并把中药库开头的 11 条「现代名→古名对照」升格为 `herb.alias` 数据），否则
   `formula_herb.herb_id` 大面积悬空、组成反查（FR-7）与五味浏览（FR-8）双双失真。
2. **性味不在 `气味` 列里**。实测该列 **379 行全为 `—`**（占位未填），真实性味藏在
   `功效·主治` 列的 `【性味】…` 标记内（295 行有标记，**88 行没有**）。
   → ETL 需正则抽取，并显式定义 88 条空值的呈现（不得让 LLM 补齐性味）。
3. **`用量` 与 `禁忌` 是同列混排**。列内含炮制、海藏引文（库内原文作「海藏曰…」）、用量、禁忌（丹砂那行约 700 字），
   实测 `禁忌` 出现 394 次、`用量` 382 次、`【炮制】` 31 次 → FR-8 的分节渲染需要拆分规则，
   拆不出的整段进 `raw_note` 原样展示，不做伪结构化。
4. **古制剂量有三分之一转不成克**（详见 FR-3 五态表与附录 B）。`方剂库-经方组成.md` 实测 1197 个剂量数据点：
   可转克 **826（69%）**，`dose_convert.py` 返回 `None` 的 **371（31%）**——其中 `枚/个/茎/片` 123、
   `分`=比例 90、`剂量见原书`/形态量词 132、`铢` 等**脚本根本没有单位分支**的 26（1两=24铢，五苓散 十八铢）。
   同一文件还实测 **31 行**含「剂量见原书」，且抽取器把「**瓜蒂散是吐剂**」「**表症**」「**冷水**」
   这类**注记当成了药味**（一物瓜蒂汤行可见）→ 必须建模换算状态（FR-3、§5.3 `dose_state`）并出悬空清单，
   否则 ETL 只能在「丢行」和「造数」之间二选一。
5. **五味归类少 1 味**：酸17 + 苦142 + 甘98 + 辛91 + 咸30 = **378 ≠ 379**（各节声明数与实际列举数一致，
   是归类表本身漏了 1 味，不是解析 bug）→ 归入 FR-13 质量清单，允许 `taste_group = NULL`。
6. **`针灸治症取穴.md` 的咳/喘命中数为 0**（实测 `grep -c "咳\|喘"` = 0）→ PIPELINE 的「咳喘无专取症节」
   特例分支是硬约束，见 §9。
7. **收录清单要写死，别引用 README**。`distilled/README.md` 只列了 10 份文档，实际有 17 个 `.md`；
   其中 `03-金匮/方剂交叉校验.md`（12,917 字符，无表格）、`03-金匮/方剂剂量换算.md`（59,744 字符 / 1,066 数据行 / 242 个子表）是**产物非源**，
   两个 `README.md`（含 `05-针灸/README.md`）是方法论说明。收录判定以**附录 A** 为准。
8. ~~顶层存在带全角括号的重复文档~~ —— 已不存在（实测 `find distilled -name "*（*"` 为空），该条作废；
   M1 计划里的全角括号排除规则保留为防御性兜底即可。
9. **两个收录源文档权限为 `0600`**：`distilled/汉唐方剂索引.md`、`distilled/02-伤寒论/临证诊断与治则补充.md`
   → Docker 只读挂载与 CI 可能读取失败，列为 M1 前置项。
10. 表格中残留 PDF 页眉/版本戳（`search.py` 的 `norm()` 已处理，复用其逻辑）。

## 2. 产品定位与用户

- **定位**：经方临床辅助问答与检索工具（学术研究/学习用途），非诊疗器械；全站强制免责声明。
- **目标用户**：
  1. 中医学习者/从业者：症状→辨证→查方→转克→取穴 的完整链路；
  2. 知识库维护者：重新蒸馏后一键重建索引，查看校验报告。
- **明确不做**（一期）：多模态（舌象图片）、处方对接药房、移动端原生 App、社区/UGC 医案。

## 3. 功能需求

### 3.1 RAG 问答（核心，对应 PIPELINE A–F 六类）

**FR-1 意图分类**：用户提问先经分类器（LLM few-shot 或规则+LLM 混合）归入 PIPELINE 的 6 类，决定走哪条编排链：

| 类别 | 编排链 | 复用 skill |
|---|---|---|
| A 辨证 | 七条基准/十问补齐 → 六经检索 → 定方 → 转克 | syndrome-differentiation |
| B 方剂 | 方名精确检索 → 组成/剂量/出处 → 交叉校验 | formula-lookup |
| C 中药 | 药名/性味检索 | herb-lookup |
| D 取穴 | 症状→穴位（含"咳嗽喘无专取穴节"特例走十二经穴位库） | acupoint-selection |
| E 医案 | 检索临床问答对 → 按 问→答→治→要诀 生成/整理 | clinical-case |
| F 综合 | A→B→D 串联，分节输出 | — |

**FR-2 混合检索**（替代 `search.py` 的在线职责）：
- 向量召回：中文 embedding 模型对"症状描述→条文/医案"做语义匹配，解决 `search.py` 只能字面/编辑距离匹配的短板；
- 关键词/结构化召回：方名、药名、穴名**精确匹配优先**（B/C 类查询不允许被模糊结果污染）；药名精确匹配必须**同时命中 `herb.name`（本经古名）与 `herb.alias`（现代名）**，否则用户问「桂枝」会直接落到语义召回（现状问题 1）；
- 两路结果合并 rerank（一期用规则加权：精确命中 > 向量分数 > 字面重叠），返回 top-k 证据，每条证据带锚点 `文件#章节#条目`。

**FR-3 生成与门禁（本系统的差异化重点）**：
- LLM 仅允许引用检索到的证据（带 `文件/章节/方#/医案号` 引用锚点）；
- **无证据必须拒答**：top 证据低于阈值时返回"本地库未收录该方/药/穴"，并列出最接近候选，不得自由发挥；
- 剂量输出遵守强制规则：结果只出**克**，古制在括号留痕（如 `茯苓 45g（三两，1两≈15g）`），换算调用 dose_convert 服务而非让 LLM 心算；
- **换算状态必须显式建模**（现状问题 4）。dose_convert 对每味药返回五态之一，前端与导出物按态区分，**禁止把近似值与精确值同样式呈现**。**实测规模**：`方剂库-经方组成.md` 的 1197 个剂量数据点中，仅 **826 个（69%）可转克，371 个（31%）返回 `None`**——这不是边缘情况：
  | `dose_state` | 触发条件（实测输出数） | 呈现 |
  |---|---|---|
  | `exact` | 两/斤/钱（1两=15g、1斤=8两=120g）— 826 | `茯苓 45g（三两）` |
  | `approx` | 升/合（`1升≈50g` 粗近似）、`枚` 命中参考值（附子/山茱萸 1枚≈15g） | `泽泻 100g（二升，升为近似）` + 橙牌「近似」 |
  | `count_only` | 枚/个/茎/片无参考值——**123**（如 大枣十二枚、桃仁三十个） | 保留 `十二枚`，克数列显示 `—`，不出数字 |
  | `absent` | `分`=比例（**90**）、`等分`、`剂量见原书`/形态量词（**132**） | `剂量未记载`，禁止 ETL 兜底造数 |
  | `unknown_unit` | 脚本无该单位分支 → `无可识别单位，保留原文`——**26**，主体是 **`铢`**（1两=24铢，五苓散 十八铢 等） | 原样显示 `十八铢`；是否为 `铢` 补实现换算，留待技术设计定（§10） |
  整方只要含一个非 `exact` 药味，方剂卡与回答卡顶部即挂「本方剂量不完全可执行」提示（NFR-4）。
- 每条回答末尾由服务端自动追加免责声明（不依赖模型自觉）；
- 输出遵循固定 JSON Schema（FR-4），前端按 Schema 渲染，而非纯文本。

**FR-4 结构化输出格式**（对齐 PIPELINE §4）：
- 辨证/医案类：`{chief_complaint, pathogenesis: [{symptom, source_ref}], treatment: {formula, source_ref, doses_g[], ancient_note}, acupoints[], tips}`；
- 方剂类：`{name, composition: [{herb, herb_id, g, ancient, dose_state}], source, indications, dose_complete}`（`dose_complete=false` 当且仅当存在非 `exact` 药味，用于挂顶部提示）；
- 中药类：`{name, alias[], flavor, flavor_state /*extracted|missing*/, effects, indications, dosage, contraindications, taste_group, raw_note}`（`flavor` 来自 `【性味】` 抽取，88 味缺失时走 `raw_note` 原样展示，不填空值；见现状问题 2/3）；
- 取穴类：`{symptom, points: [{name, location, role(五输/原/络/郄/募), action}], logic}`；
- `source_ref` 必须可点击回溯到原文段落（溯源见 §5.4 evidence 接口）。

**FR-5 引导式问诊**（A/F 类信息不全时）：
- 按七条基准 + 十问生成结构化追问表单/多轮提问（寒热/汗/便/饮/胸/冷/睡眠/妇女/音声）；
- 用户回答累积进会话上下文，再次进入辨证链。

**FR-6 会话管理**：多轮对话、历史持久化、每轮问答保留完整证据链。

### 3.2 知识检索浏览（前端四大库页面，纯 CRUD 不走 LLM）

- **FR-7 方剂库**：按六经（伤寒）/病脉证篇（金匮）/方# 浏览与筛选；支持组成反查（"含麻黄的方"，依赖药名归一后的 `herb_id` join，反查同样接受古名/现代名）；详情展示两版本剂量对照 + 交叉校验标记（来自 formula_verify）+ **本方剂量完整度**（`dose_state` 非 exact 的药味单独成列显示原样古制）。
- **FR-8 中药库**：379 味按名字/功效检索——检索名同时覆盖**本经古名与现代别名**（`牡桂`/`桂枝` 都能进同一条目，见现状问题 1）；按五味（酸17/苦142/甘98/辛91/咸30，合计 378，**1 味未归类**）→五脏浏览，未归类味显示在「其他/未归」分组而非静默丢弃；详情页性味缺失的 88 味显示「本经未载性味」，不生成推测文案。
- **FR-9 针灸穴位**：十二经穴位库（井荣俞经合/原络郄募角色）+ 按症取穴。
- **FR-10 医案**：30 例问答对浏览、按病类筛选；辨证链中作为 few-shot 范例展示。
- **FR-11 辨证框架页**：六经传变图 + 治则七法（静态渲染 `六经辨证框架.md`/`核心理论文档.md`）。

### 3.3 管理端（知识库维护者）

- **FR-12 重建索引**：一键 ETL→切片→embedding→入库 全流程（`distilled/` 更新后执行）；显示增量 diff（新增/删除的方、药、穴数）。
- **FR-13 数据质量报告**：复用 formula_verify / skills_validate 逻辑，六张清单——① 药材差异；② 剂量偏差>50%；③ 解析失败的表格行；④ **注记被误抽为药味**（实测「瓜蒂散是吐剂」「表症」「冷水」这类行，见现状问题 4）；⑤ **`formula_herb.herb_id` 悬空**（药名归一未覆盖的差集，即 FR-7 反查与 FR-8 浏览的失真面）；⑥ **换算状态分布**（`exact/approx/count_only/absent` 各多少味，含 1 味未归五味、88 味无性味）。①–⑥ 全部可按源文件路径下钻，作为 M1 的解析覆盖率门禁输出。
- **FR-14 原文兜底查询**：对 `text/*.txt` 的 grep 式检索接口（仅供溯源展示，不直接进生成，维持"distilled 优先"纪律）。
- **FR-15 问答日志**：记录 query、意图分类结果、检索命中、是否触发拒答，用于迭代检索阈值与语料补缺。

## 4. 非功能需求

| 编号 | 要求 |
|---|---|
| NFR-1 | 问答首字响应 < 3s（SSE 流式输出），完整回答 < 15s |
| NFR-2 | 检索 P95 < 500ms（300K 级语料量级，单机可承载） |
| NFR-3 | **可溯源性**：100% 生成内容带出处锚点；无出处内容只允许出现在独立"通用框架"字段且前端灰字标注 |
| NFR-4 | 剂量安全一致性：同一方在任何入口（问答/浏览/导出）显示的克数必须同源一致；且 `dose_state` 与换算留痕同源一致——近似/未换算量不得在任何入口被显示为精确克数（FR-3 五态表、附录 B） |
| NFR-5 | 免责声明覆盖所有回答与导出物 |
| NFR-6 | 语料只读、版本化：索引绑定 `distilled/` 的 git commit hash，可回滚 |
| NFR-7 | 部署：单 docker compose 可起（API + DB + 前端），embedding 允许本地模型，语料可不出域 |

## 5. 技术方案（推荐，待确认后细化设计）

### 5.1 选型总览

| 层 | 选型 | 理由 |
|---|---|---|
| 前端 | **Next.js + React + Tailwind**（Vue3+Vite 备选） | SSR 利于四大库浏览页首屏；聊天流式 UI 生态成熟 |
| 后端 | **Python FastAPI** | 与现有 scripts 同语言，`search.py` 解析/打分、`dose_convert.py`、`formula_verify.py` 可直接 import 复用，零移植成本 |
| 数据库 | **PostgreSQL + pgvector** | 结构化（方/药/穴/医案表）与向量同库，混合检索一条 SQL 可 join；语料量小，无需独立向量库 |
| Embedding | **BGE-M3**（本地，TEI 或 sentence-transformers） | 中文语义检索好、开源可自部署，满足 NFR-7；备选：国产大模型 API embedding |
| LLM | 可配置 provider（Claude/Qwen/GLM） | 5 个 SKILL.md 正文直接改写成各编排链的系统提示词；输出用 JSON Schema 强约束 |

### 5.2 RAG 数据流

```
distilled/*.md ──ETL(复用 search.py 解析)──▶ 结构化表 ──┐
                    │  (formulas/herbs/acupoints/cases    ├─▶ 混合检索 ─▶ rerank ─▶ LLM 受约束生成 ─▶ Schema 化回答
                    │   /framework_docs)                  │        ▲
                    └─▶ 切片(按表格行/医案条/框架小节) ─▶ pgvector ┘   证据锚点(file#section#item)
                                                    ▲
                          重建索引(FR-12) + 质量报告(FR-13，复用 formula_verify)
```

### 5.3 核心数据模型（PostgreSQL）

```
formula(id, name, source_doc, section /*六经或金匮病篇*/, formula_no /*经典配方方#*/,
        indication, ancient_text)
formula_herb(formula_id, herb_id, herb_text /*组成列原文药名，可能含炮制后缀*/,
             dose_g /*可空：非 exact 态不填数值*/, dose_ancient,
             dose_state /*exact|approx|count_only|absent|unknown_unit*/, conversion_note)  -- dose_convert 留痕
herb(id, name /*本经古名，如 牡桂/茈胡*/, alias[] /*现代名，来自中药库对照表+同义词归一*/,
     flavor /*从「功效·主治」列的【性味】抽取，非源表气味列*/,
     flavor_source_state /*extracted|missing(实测88味)*/,
     effects, indications, dosage_note, taboo, preparation /*【炮制】31处*/,
     raw_note /*拆不出的混排原文整段*/,
     taste_group /*酸苦甘辛咸，允许 NULL：实测378/379*/, organ_group /*五脏*/)
```

> ⚠️ **`herb_id` 不是白送的**：`中药库` 用古名、`经方组成` 用现代名（现状问题 1），ETL 必须做
> 「炮制前缀剥离 → 同义词/别名归一 → 未命中进 FR-13 ⑤ 悬空清单」三步，`formula_herb.herb_text`
> 保留原文以支持回溯。**在悬空清单清零前，FR-7 组成反查与五味浏览的结果不完整，不得当作已完成。**
> 另：本节 `formula` 仍是单表，尚无法表达四个来源（经典配方/经方组成/金匮病段/伤寒六经方库）
> 的同名方差异与出处编号体系（`方#` vs `第25条` vs `病段`）——该建模属未评审项，见 §10。
acupoint(id, name, meridian /*十二经*/, role /*五输/原/络/郄/募*/, location, actions)
acupoint_symptom(acupoint_id, symptom, source_doc)
case(id, no /*医案问NN*/, category, chief_complaint, pathogenesis,
     treatment_formula_ids, tips, raw_md)
framework_chunk(id, doc /*六经框架/内经核心理论/临证补充*/, section, content, chunk_order)
chunk_vector(id, ref_type, ref_id, content, embedding vector(1024))  -- 所有可检索文本切片
answer_log(id, query, intent_class /*A-F*/, evidence_refs jsonb, refused bool, created_at)
```

### 5.4 API 设计（一期）

| 端点 | 说明 |
|---|---|
| `POST /api/chat` | 多轮问答；SSE 流式；内部：意图分类→检索→(dose_convert/verify 工具)→受约束生成 |
| `POST /api/search` | 混合检索裸接口（前端联想/调试用）：query, kind[], section, top |
| `GET /api/formulas` `/api/formulas/{id}` | 方剂列表/详情（含两版本剂量对照、校验标记） |
| `GET /api/herbs` `/api/acupoints` `/api/cases` | 各库浏览 |
| `GET /api/evidence/{ref}` | 证据原文回溯（回答中引用角标点击） |
| `POST /api/tools/dose-convert` | 封装 dose_convert.py，返回 `{g, dose_state, trace}`。**以下为脚本实测输出**（1斤=8两=120g，故 半斤=60g 而非 180g）：`半夏 半斤` → `{g:60, state:"exact", trace:"0.5斤×120g=60.0g"}`；`桂枝 三两` → `{g:45, state:"exact"}`；`泽泻 二升` → `{g:100, state:"approx", trace:"2×~50g"}`；`附子 一枚` → `{g:15, state:"approx", trace:"枚参考值"}`；`大枣 十二枚` → `{g:null, state:"count_only", trace:"按物而异，保留数量"}`；`甘草 二分` → `{g:null, state:"absent", trace:"分=比例，非绝对剂量"}`。换算依据的唯一来源是 `scripts/dose_convert.py`，接口与前端**不得自算**（附录 B 是逐单位实测表） |
| `POST /api/admin/reindex` / `GET /api/admin/quality-report` | 管理端 |

### 5.5 前端页面（概览）

1. **对话页**（核心）：聊天流 + 结构化卡片（方剂表/药卡/穴位表按 FR-4 Schema 渲染）+ 出处角标弹层 + 问诊引导表单（A/F 类）+ 底部常驻免责声明；

3. **辨证框架页**：六经传变可视化（静态）；
4. **管理页**：重建索引 + 进度、质量报告、问答日志（含拒答率看板）。

## 6. 前端交互设计

> 交互设计的总原则与后端门禁一致：**让用户一眼看出"哪句话有库内出处、哪句是框架组织语、哪条被拒答"**。溯源不是隐藏功能，而是对话页的第一公民。

### 6.1 全局框架

```
┌────────────────────────────────────────────────────────┐
│ 顶栏：Logo ｜ 对话 ｜ 方剂库 ｜ 中药库 ｜ 针灸 ｜ 医案 ｜ 辨证框架 ｜ 管理 │
├──────────┬──────────────────────────────┬──────────────┤
│ 会话列表   │        主内容区                │  溯源抽屉      │
│ (对话页    │  (路由切换：对话/四大库/框架/管理) │  (全局右滑，    │
│  左侧，可   │                              │   仅对话页常驻)  │
│  折叠)     │                              │              │
├──────────┴──────────────────────────────┴──────────────┤
│ 底部常驻免责条："执业中医师面诊；本库为学术蒸馏产物，非诊疗建议"      │
└────────────────────────────────────────────────────────┘
```

- **布局**：对话页三栏（会话列表 240px 可折叠 / 主区 min 720px / 溯源抽屉 400px 覆盖式）；浏览类页面两栏（筛选面 280px + 列表）。
- **路由**：`/chat`、`/chat/:sessionId`、`/formulas`、`/formulas/:id`、`/herbs`、`/herbs/:id`、`/acupoints`、`/cases`、`/framework`、`/admin/*`；四大库列表的筛选/分页/搜索词**全部同步到 URL query**（可分享、可回退、SSR 首屏直出）。
- **响应式断点**：≥1280px 三栏；768–1279px 会话列表自动折叠、溯源抽屉改为全屏 Modal；<768px 单栏，抽屉改底部滑出（一期只保证可用，不做移动专精）。
- **免责条**：视口固定底部，不随滚动消失（NFR-5）；回答卡片内另有服务端拼接的免责尾注，两层并存。
- **视觉基调**：宣纸底色 + 墨色主文 + 朱砂色强调（出处角标/关键病机）；古籍引文用衬线字体、白话解释用无衬线，从字体上区分"库内原文"与"组织语"。键盘可达与对比度按 WCAG AA 自检（问诊表单必须可纯键盘完成）。

### 6.2 对话页交互（核心流程）

**6.2.1 提问→回答的状态机**（对用户可见，消除"黑盒等待"）：

```
发送 → [意图识别中] → [检索本地库…] → [生成中·流式] → [完成]
              │              └ 命中不足 → [拒答卡]
              └ 显示意图徽章（A辨证/B方剂/C中药/D取穴/E医案/F综合）
```

- 输入框 Enter 发送、Shift+Enter 换行；发送后立即出现**骨架气泡**。
- **意图徽章**：回答气泡顶部常驻小徽章（如 `辨证 A`），hover 说明"该问题走了 syndrome-differentiation 编排链"——把内部编排透明化，也方便日志核对分类正确率。
- **检索进度**：进度文案实时显示"命中 12 条本地证据（伤寒方 4 / 中药 5 / 医案 3）"，点击直接展开当轮证据面板。
- **流式渲染**：文本 token 流式追加；结构化卡片（方剂/药/穴）在字段完整后**整体替换**占位骨架，不出现半张表格——剂量数字尤其禁止"先显示一半再补齐"（避免误读，NFR-4）。
- 生成中允许停止（保留已出内容并标注"已中断"）；SSE 断线自动重连一次，失败则显示"回答未完成，重试"按钮。

**6.2.2 出处角标与溯源抽屉**（全局最重要的交互）：

- 正文中每个来自库内的结论尾部带角标 `[1]`（朱砂色上标）；**同一来源复用同一编号**，一个角标可挂多条原文。
- **hover**：350ms 延迟浮出摘要卡（文件名 + 章节 + 命中句前 60 字），移开即收，不打断阅读。
- **点击**：打开右侧溯源抽屉，显示完整证据列表——每条含原文段落（命中句高亮）、出处 `文件#章节#方#/医案号`、"在库详情页打开"跳转链接、"复制引用"按钮。
- 角标密度规则：逐条病机对应（FR-4 `pathogenesis[]`）天然一句一标；连续同证据的句子不重复标注，避免"文字满屏角标"。
- **无出处的组织语**（D1 的 `general_note`）：灰底虚线框 + 前缀"通用框架说明（非本库内容）"，样式上与正文显著区隔，且**不带角标**。

**6.2.3 结构化卡片交互**：

- **方剂卡**：表头固定四列（药味/克数/古制原量/换算留痕）；提供「克 ↔ 古制」开关，默认显示克（NFR-4），切到古制时整列替换并在表尾附换算标准 `1两≈15g`；`dose_state` 非 `exact` 的药味，克数列显示 `~100g`（近似，橙牌）或 `—`（未换算/仅计数）并 tooltip 出 `conversion_note`，**全方含任一非 exact 即表头挂「本方剂量不完全可执行」**；卡片底部展示出处（篇/条/方#）与**交叉校验徽章**：两版本一致=灰勾，药材差异=黄牌（点开显示差异明细），仅单版本=蓝牌"未交叉校验"。
- **中药卡**：性味/功效/主治/禁忌分节；五味→五脏以标签 chip 展示，chip 可点击跳中药库五味筛选视图。
- **穴位卡**：按经络分组，每条显示角色徽标（五输/原/络/郄/募，不同底色）；同症多穴时给出"主穴/配穴"层次——直接消费 FR-4 的 `logic` 字段，不让用户自己猜取穴逻辑。
- **医案卡**：按 PIPELINE 的 问→答→治→要诀 四段渲染，段间折叠（默认展开问/治，收起答/要诀），且与库内 30 例做"相似医案"侧挂链接。
- 所有卡片支持：复制为 Markdown、整轮回答导出（导出物自动带免责与出处尾注，NFR-5）。

**6.2.4 拒答卡**（FR-3 的前端呈现，拒答≠报错）：

- 文案固定："本地库未收录「××」"，附检索过程摘要（查了哪些库、最高分多少）——让用户理解"查不到"是纪律不是故障。
- 下方给**最近候选 chips**（如问"桂枝麻黄各半汤"时给出"桂枝汤 / 麻黄汤 / 大青龙汤"），点击即以其重新提问。
- 提供兜底按钮「在原文(text/)搜一下」→ 触发 FR-14，结果只在抽屉里以"原文线索，未经蒸馏校验"样式展示，不进对话正文。

**6.2.5 会话与反馈**：

- 左侧会话列表：新建/重命名/删除，按最后提问时间倒序；每轮问答保留证据链，重新打开会话可完整回放角标。
- 输入框上方常驻**快捷追问 chips**（由后端在回答尾部附带生成，如"该方剂量换算""配穴方案"），点击直接发送。
- 每条回答👍/👎+可选一句话原因，写入 `answer_log`（FR-15），管理页日志看板可按👎筛选 bad case。

### 6.3 引导式问诊交互（A/F 类，FR-5）

触发时机：辨证链判定信息不全时，回答末尾插入**问诊卡**（非弹窗，保持在对话流内，可随时跳过）。

- 问诊卡 = 七条基准（额凉手足温/胃口/睡眠/大便/小便/精神/脉）逐条三态开关：`正常 / 异常 / 不清楚`；选"异常"展开一行自由文本（如"小便一天 10 次，夜间 3 次"）。
- 十问（寒热/汗/头身/便/饮/胸/冷/别/妇/声）作为第二屏标签页，同样"只问缺失项"——已在前文提到的症状自动预填并标"已从您的描述提取"，用户只需确认或修正。
- 提交后生成一段**主诉摘要**（结构化，含逐条基准对照结果）回填为一条新的用户消息，重新进入辨证链；摘要中每个提取项保留来源（用户本轮填写 or 历史对话）。
- 允许"跳过问诊直接要答案"：按钮保留，但答案卡顶部标注"基于不完整信息，以下辨证仅供参考"（对应 PIPELINE 的严谨性，又不阻塞体验）。
- 键盘操作：Tab 遍历三态开关，空格切换，Enter 提交。

### 6.4 四大库浏览交互

**列表页（方剂/中药/针灸/医案通用模式）**：

- 顶部检索框：**即时联想**（debounce 250ms 调 `POST /api/search`），下拉分组显示"方名精确 / 药名精确 / 穴名精确 / 语义相关"——精确组优先，与 FR-2 的"精确匹配优先"一致；回车进结果列表。
- 左侧筛选面：方剂库=六经多选 + 出处文档 + 是否含交叉校验差异；中药库=五味多选 + 归五脏 + 性（寒热温平）；针灸=经络 + 穴位角色；医案=病类。筛选即时生效，URL 同步，支持"复制当前筛选链接"分享给他人。
- 列表行：主名 + 出处摘要 + 徽标（校验状态/五味 chip）；行内不展开详情（保持扫读节奏），点击进详情。
- 方剂库特有：**组成反查**入口（输入药名→列出含该药的所有方，按六经分组），复用 `formula_herb` 表 join。

**详情页**：

- 版式：基本信息卡（顶部）+ 组成/功效分节 + 原文节选（引用块样式，衬线字体）+ 校验明细（黄牌差异逐行列出）+ 关联推荐（同方药味、同篇方剂、相关医案）。
- 固定动作按钮「就本条提问」：跳转 `/chat` 并携带 `source_ref` 上下文（输入框预填"关于 桂枝汤（伤寒论·太阳篇）…"），实现浏览→问答的闭环。
- 「古↔克」开关与对话页方剂卡行为一致（同一份 dose 数据，保证 NFR-4）。

**辨证框架页**：六经传变用 SVG 交互图——点某经高亮其入传路径 + 右侧面板列出该经治则与代表方（点击方名跳方剂详情）；治则七法为锚点目录。静态数据、SSR 直出，无加载态。

### 6.5 管理端交互

- **重建索引**：按钮 → 二次确认（显示当前索引 commit hash → 目标 hash 的 `distilled/` diff 摘要：+N 方 / -N 药…）→ 进入进度页（阶段流水：ETL→切片→embedding→入库→校验，各阶段耗时与失败计数；完成后展示增量 diff 报告）。重建期间旧索引保持可用（蓝绿切换），页顶横幅提示"当前正在使用索引 vX（重建中）"。
- **质量报告**：三张表（药材差异 / 剂量偏差>50% / 解析失败行），支持筛选+导出 CSV；"解析失败行"点击可跳到对应 distilled 源文件路径，指引维护者修数据。
- **问答日志**：表格列=query/意图/命中数/是否拒答/👎标记；顶部四个小卡片看板（日活 query 数、拒答率、平均证据命中数、分类分布），拒答列表按频次排序——高频拒答词即语料补缺清单（反哺 `distilled/`）。
- 管理页整体弱交互（表格为主），不做花哨动线，一切操作可回溯。

### 6.6 全局状态与异常（设计穷举）

| 场景 | 表现 |
|---|---|
| 检索 0 命中 | 拒答卡（6.2.4），非空白页 |
| LLM/后端超时 | 气泡内错误条"生成失败，重试/换浏览页查询"，保留已完成的检索进度信息 |
| SSE 中断 | 自动重连 1 次；仍失败则标注"回答未完成" |
| 索引重建中 | 全站顶部横幅提示索引版本；问答用旧索引不中断 |
| 四大库空列表 | 空状态插画 + "换个筛选/去对话页问"引导 |
| 证据接口失效（原文被重构） | 抽屉显示"该出处在当前索引版本不存在"并给当前版本近似锚点 |
| 离线/弱网 | 浏览页 SSR 缓存页可读；对话页提示不可用 |

## 7. 关键设计决策（需评审确认）

| # | 决策点 | 本文档立场 |
|---|---|---|
| D1 | LLM 是否允许"通用中医知识"补充 | **不允许进正文**；只允许在独立字段 `general_note` 输出且前端标注"非本库内容，仅供参考"（对应 CLAUDE.md 分层规则） |

| D3 | embedding 自部署 vs API | 首选自部署 BGE-M3（NFR-7 + 语料不出域）；无 GPU 环境退化为 API |

## 9. 风险与对策

- **表格解析噪声**（distilled 表格格式不完全统一）→ M1 先出解析覆盖率报告，未解析行进质量清单人工修，不让脏数据进向量。**已量化**：经方组成 1197 个剂量数据点里 31% 转不成克、注记被误抽为药味（现状问题 1/4），所以「解析覆盖率报告」不是可选项而是 M1 的退出条件。
- **中药库与方剂库两套药名体系**（古名 vs 现代名）→ 归一表是唯一解，且必须可回溯（保留 `herb_text` 原文）。风险在于归一表覆盖不全时**静默丢药味**：`herb_id` 悬空必须报错进 FR-13 ⑤，不允许 `ON CONFLICT DO NOTHING` 式吞掉。
- **LLM 绕过门禁臆造剂量** → 剂量字段一律由 dose_convert 工具产出并直填 Schema，生成模型不接触数字写入。
- **"咳嗽喘"类特例**（针灸治症取穴无该节）→ 编排链内置代码分支（走十二经穴位库列缺/照海 + 俞募肺俞/中府），不依赖提示词。
- **语料更新流程断裂** → 约定：`distilled/` 变更后 CI 或手动触发 FR-12 重建，索引版本随 git hash 走。

## 附录 B · `dose_convert.py` 逐单位实测输出（换算口径唯一来源）

常量：`1两=15g`、`1斤=8两=120g`、`1钱=1.5g`；`枚` 参考值仅 `附子/山茱萸 = 15g`；`升/合 ≈ 50g`（粗近似）。

| 输入 | 脚本实测输出 | `dose_state` |
|---|---|---|
| `桂枝 三两` | `3.0两×15g=45.0g` | `exact` |
| `半夏 半斤` | `0.5斤×120g=60.0g` | `exact` |
| `泽泻 二升` | `2.0×~50g≈100.0g（升近似）` | `approx` |
| `芒硝 三合` | `3.0×~50g≈150.0g（升近似）` | `approx` |
| `附子 一枚` | `1.0×15.0g=15.0g（枚参考值）` | `approx` |
| `大枣 十二枚` | `12枚（枚/个按物而异，保留数量）` | `count_only` |
| `瓜蒂 二十个` | `20个（枚/个按物而异，保留数量）` | `count_only` |
| `甘草 二分` | `分=比例，非绝对剂量` | `absent` |
| `各药 等分` | `各取等量，无绝对剂量` | `absent` |
| `…（剂量见原书）` | `形态量词/见原书，按临床` | `absent` |
| `猪苓 十八铢` | `无可识别单位，保留原文` | `unknown_unit` |

**全库分布实测**（`方剂库-经方组成.md` 242 方 / 1,197 个剂量数据点）：

| 态 | 数据点 | 占比 |
|---|---|---|
| 可转克（`exact`/`approx`） | 826 | 69% |
| `count_only`（枚/个/茎/片） | 123 | 10% |
| `absent`（剂量见原书/形态量词 132、分=比例 90） | 222 | 19% |
| `unknown_unit`（主体为 `铢`，1两=24铢 未实现） | 26 | 2% |
